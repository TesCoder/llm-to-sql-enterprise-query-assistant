# LLM-to-SQL Enterprise Query Assistant

**Databases shouldn’t require a translator.**  
**Ask in plain English — get the SQL and the answer.**

This system delivers a polished `LLM-to-SQL` product experience: a clean browser UI where non-technical users ask business questions and receive **SQL-backed results** with full transparency and production-oriented safety.

Modern teams run on data — but SQL still creates a bottleneck. This product removes that friction by turning natural language into transparent, executable queries and structured results you can trust.

## Start here: the Ask UI (`/ui`)
Open `http://127.0.0.1:8000/` (redirects to `/ui/`).

- **User-first**: one page, one box, clear examples
- **Transparent by default**: every response is structured and includes `sql` (when executed), `rows`, and `row_count`
- **No SQL required**: non-technical users ask questions; the system runs the query
- **Designed for reliability**: a curated **presets-first** library provides deterministic NL → SQL for common questions

Try these:
- `Show total sales by region`
- `Show total sales by category`
- `What are the top 10 states by sales?`
- `How many unique orders are in the dataset?`

To teach it your org’s recurring questions, add/edit presets in `nl2sql/presets.json` (no UI changes required).
Today the system runs a **presets-first** NL → SQL layer for reliability, with an LLM fallback for questions that don’t match a verified preset.

Also included:
- `http://127.0.0.1:8000/manual/` — a manual SQL console (calls `POST /query`)
- `http://127.0.0.1:8000/docs` — interactive API docs

## Why this matters
Business teams run on data, but SQL turns insight into a queue:
- **Analysts become gatekeepers** for every “quick question”
- **Decisions slow down** while teams wait for queries and dashboards
- **Context gets lost** as questions bounce between people and tools

`LLM-to-SQL` flips that model. Instead of learning SQL (or waiting on someone who knows it), teams ask questions naturally—then get a precise, executable query and a structured answer.

Insight shouldn’t depend on who knows SQL.

## Product demo flow
User types:

```text
Show total sales by region
```

System:
→ checks for a reviewed preset match  
→ if no match, generates SQL with the LLM (schema-grounded)  
→ executes safely  
→ returns a structured response (SQL + rows)

Example SQL (excerpt):

```sql
SELECT o.region, SUM(oi.sales) AS total_sales
FROM order_items oi
JOIN orders o ON o.order_id = oi.order_id
GROUP BY o.region
ORDER BY total_sales DESC
LIMIT 200
```

Response shape (excerpt):

```json
{
  "status": "ok",
  "source": "verified",
  "preset_id": "sales_by_region",
  "sql": "SELECT o.region, SUM(oi.sales) AS total_sales FROM order_items oi JOIN orders o ON o.order_id = oi.order_id GROUP BY o.region ORDER BY total_sales DESC LIMIT 200",
  "row_count": 4,
  "rows": [{ "region": "West", "total_sales": 710219.6845 }]
}
```

Notes:
- `source`: `"verified"` when a question matched `nl2sql/presets.json`, `"llm"` when SQL was generated by the model
- `preset_id`: present only when `source="verified"`
- In the Ask UI (`/ui`), toggle **Dev** in the footer to view `Source`, `Verified ID`, executed SQL, and debug JSON.

## Technical architecture
This repo is clean, modular, and easy to extend:
- **Ask UI**: static app in `ui/` (served by FastAPI at `/ui/`) that calls `POST /ask`
- **Manual SQL console**: static app in `manual/` (served at `/manual/`) that calls `POST /query`
- **Backend API**: `service/app.py` (FastAPI + async DB)
- **Preset engine**: `nl2sql/presets.json` + matcher in `nl2sql/presets.py`
- **Schema grounding**: `nl2sql/schema.py` (SQLite introspection + small categorical “value hints” to reduce hallucinations)
- **LLM client/prompting**: `nl2sql/llm.py` (DeepSeek by default; OpenAI-SDK compatible)
- **Local database**: `enterprise.db` (SQLite) built from `data/train.csv` via `data/load_data.py`

### API endpoints
- **`GET /health`** → `{ "status": "ok" }`
- **`POST /ask`** → presets-first NL questions backed by `nl2sql/presets.json`, with LLM fallback when there’s no preset match
- **`POST /query`** → safe, read-only SQL execution (developer/analyst path)

### Production-oriented safety
SQL execution is guarded at the API layer:
- **SELECT-only**: blocks DDL/DML and unsafe keywords
- **Single-statement only**: blocks multi-statement queries
- **Safety limit**: appends `LIMIT 200` when missing
- **Server-side validation**: model prompts help, but the API re-validates generated SQL before execution
- **One-shot repair retry**: on LLM SQL execution errors, the system retries generation once with the DB error (keeps cost bounded)

## Extensibility
The current presets-first layer is the reliability foundation. The architecture is designed to support:
- **Schema-aware NL → SQL generation** (LLM-backed inference with grounding)
- **Stronger SQL validation** (AST parsing / allowlists)
- **Retrieval over schema metadata and business definitions**
- **Multi-database connectors** (Postgres, Snowflake, BigQuery)
- **Role-aware policies and audit logging**

## Configuration
- **`DATABASE_URL`**: defaults to `sqlite+aiosqlite:///./enterprise.db`
  - Set via `.env` (loaded automatically) or your shell environment.

- **LLM (DeepSeek by default)**: for LLM fallback when there’s no preset match, set in `.env`:
  - `OPENAI_API_KEY=...` (DeepSeek key)
  - `OPENAI_API_URL=https://api.deepseek.com/v1`
  - Optional: `DEEPSEEK_MODEL=deepseek-chat`
  - Connection test: `python nl2sql/llm.py --ping`

## Example requests
Run a raw SQL query:

```bash
curl -X POST http://127.0.0.1:8000/query \
  -H "Content-Type: application/json" \
  -d '{"sql":"SELECT COUNT(*) AS orders_count FROM orders"}'
```

Ask a preset-backed question:

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"Show total sales by region"}'
```

Ask a non-preset question (LLM fallback):

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"Show me a city with the highest number of phone orders"}'
```

## Presets (natural language → SQL)
Presets live in `nl2sql/presets.json`.

Matching is exact after normalization (lowercase, punctuation removed, whitespace collapsed) against each preset’s `canonical` and `aliases`.

Add a new preset (example shape):

```json
{
  "id": "sales_by_ship_mode",
  "canonical": "show total sales by ship mode",
  "aliases": ["sales by ship mode", "sales by shipping mode"],
  "sql": "SELECT o.ship_mode, SUM(oi.sales) AS total_sales FROM order_items oi JOIN orders o ON o.order_id = oi.order_id GROUP BY o.ship_mode ORDER BY total_sales DESC"
}
```
